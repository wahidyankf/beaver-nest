## Entries

- **2026-08-26 — A watched development server is not a stable routed backend.** Safe evidence: the proxy remained configured while local and routed application requests returned 500 after dependency/configuration changes; same-pane restart restored 200 responses, and the routed endpoint was then moved only after a separate warm backend passed root and chat checks. Decision: keep the legacy browser journey available until verified cutover, interrupt plan work on any health failure, and route repeatable rollout infrastructure to [Zero-downtime local rollouts](../../ideas/q1-urgent-important/zero-downtime-local-rollouts.md) plus the [live-service continuity standard](../../../repo-governance/development/live-service-continuity.md).
- **2026-08-26 — HTTP success does not prove a LiveView browser connection.** Safe evidence: an isolated setup page returned 200 while its WebSocket origin was rejected because the E2E browser used `127.0.0.1` and the endpoint declared `localhost`; matching the exact origin removed the reconnect loop and the 22-case authentication browser suite passed. Decision: the permanent [end-to-end testing standard](../../../repo-governance/development/end-to-end-testing.md) now requires exact browser/application origin matching and treats connection errors as failures.
- **2026-08-26 — LiveView readiness and user-path isolation are separate E2E preconditions.** Safe evidence: a login form occasionally submitted an empty username when the first LiveView patch replaced inputs filled before `phx-connected`; after that was fixed, parallel device projects still changed one shared user's import count. Waiting for the connected root and assigning one `test-user-` identity per device project made the 25-case centralized-data matrix deterministic. Decision: both requirements now live in the [end-to-end testing](../../../repo-governance/development/end-to-end-testing.md) and [test identity](../../../repo-governance/development/test-identities.md) standards.
- **2026-08-26 — Password work must not block session reads or unrelated logins.** Safe evidence: the first implementation performed Argon2 verification inside one identity coordinator, so parallel login requests queued behind a CPU-bound operation. Login verification and per-session reads/writes now execute concurrently against immutable account records and path-scoped storage; only one-time bootstrap remains coordinated. Decision: the final identity boundary is documented in [technical documentation](tech-docs/README.md#identity-and-session-boundary) and protected by integration coverage for coordinator independence plus parallel browser logins.
- **2026-08-26 — Functional browser coverage does not prove changed UI accessibility or wording.** Safe evidence: all 163 desktop/tablet/mobile E2E cases passed, while focused browser audit still found one 2.12:1 chat-label contrast failure, two low-contrast learning labels, and stale tab-only persistence copy. Corrected representative light/dark states reached Lighthouse accessibility 100 with no narrow-viewport overflow. Decision: the focused requirement now lives in [end-to-end testing](../../../repo-governance/development/end-to-end-testing.md); the permanent UI copy and colors live in the app.
- **2026-08-26 — Failed thread resume needs an explicit transport event, not text matching.** Safe evidence: the deterministic runner failed a resumed thread before emitting `thread.started`; after `resume_failed` crossed the port boundary, ChatLive retained every transcript message, persisted a null thread ID, and opened a fresh session. Decision: the no-loss behaviour is canonical in [centralized data Gherkin](../../../specs/apps/bnest/app/behaviours/centralized_data.feature), the [C4 model](../../../specs/apps/bnest/app/architecture.md), and [technical reconciliation](tech-docs/README.md#implementation-reconciliation).
- **2026-08-26 — A stable candidate must be compiled and started with the same compile-time environment.** Safe evidence: the permanent, unrouted candidate rejected startup when its stable-mode endpoint setting differed from the watched dev build; the routed backend stayed healthy, and recompiling with stable mode produced a valid login/setup candidate. Decision: [development server restart](../../../repo-governance/workflows/development-server-restart.md) now makes environment-matched compilation a promotion prerequisite, and the existing [zero-downtime rollout idea](../../ideas/q1-urgent-important/zero-downtime-local-rollouts.md) owns future automation.
