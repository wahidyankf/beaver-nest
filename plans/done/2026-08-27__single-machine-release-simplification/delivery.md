# Delivery

## Execution Rules

Follow [plan execution](../../../repo-governance/workflows/plan-execution.md), [rules propagation](../../../repo-governance/workflows/rules-propagation.md), and [live-service continuity](../../../repo-governance/development/live-service-continuity.md). The [Caddy deployment workflow](../../../repo-governance/workflows/development-caddy-deployment.md) remains mandatory while Caddy is the active route. Any execution change that creates, changes, moves, or deletes a rule must run the rules-propagation idempotence gate, update the shortest point-of-use directive and canonical owner when needed, deduplicate affected guidance, and prove repository validation. The user first authorized only plan documentation and deferred implementation. The current explicit direction authorizes this plan's quality gate, execution, commits and pushes to `origin/main`, and final routed production verification; that later direction activates the phases below without expanding their scope.

## Acceptance Traceability

- `[AC-01]` Current condition is accurately recorded.
- `[AC-02]` Every alternative is compared with its own diagram, exact ports, resource formula, test impact, WebSocket behavior, migration behavior, rollback, and supported verdict.
- `[AC-03]` An open page or future multiplayer session automatically recovers authoritative state from release interruption without manual reload, missing/duplicate actions, or progress loss.
- `[AC-04]` One revision-bound, fail-closed state machine runs deterministic tests before build and emits concise structured evidence.
- `[AC-05]` The plan gives one ranked, evidence-backed recommendation without implying implementation approval.
- `[AC-06]` Supported Mermaid label segments have deterministic limits and fail pre-push before clipped release text can be accepted.
- `[AC-07]` Production, candidate, development, test, and E2E ports have one owner and fail closed on collision.
- `[AC-08]` Current data and future database/schema changes follow one lock-owned expand–migrate–verify–contract lifecycle and preserve rollback compatibility.
- `[AC-09]` Execution applies the rules-propagation workflow to every affected repository rule and proves a change or verified no-op.
