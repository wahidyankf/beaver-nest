# Learnings

## Capture Rule

Record only safe facts: source revision, target name, port role, pass/fail, duration, aggregate process resource values, and anonymous synthetic-journey outcome. Do not record machine paths, hostnames, Tailscale identity, credentials, cookies, keys, user names, user records, request payloads, or logs containing them.

## Observations

- **2026-08-27 — Repository release baseline.** `bnest-app` exposes `proxy:install`, `proxy:status`, `release:build`, `deploy:prepare`, `deploy:promote`, `deploy:rollback`, and `deploy:retire` through Nx. Its deployment script starts the candidate with LaunchAgents, checks `/health/ready` plus `X-Bnest-Revision`, and switches Caddy through a graceful reload. Disposition: retained in [current condition](tech-docs/README.md#current-condition).
- **2026-08-27 — Runtime observation unavailable in this shell.** `proxy:status` stopped before it could inspect Caddy because `BNEST_DEPLOY_ROOT` was not set. This is expected secret-safe configuration validation, not evidence of outage. Disposition: defer actual baseline collection to Delivery Phase 1 with an authorized machine-local environment.
- **2026-08-27 — Prior art found.** [Zero-downtime local rollouts](../../ideas/q1-urgent-important/zero-downtime-local-rollouts.md) predicted the need for an immutable candidate, a stable proxy, rollback, and bounded cleanup. Disposition: the formal plan records the now-implemented baseline; no duplicate idea is created.
- **2026-08-27 — Primary documentation checked.** Official LiveView/Channels guidance confirms automatic reconnect/rejoin and catch-up parameters but warns state can be lost; Presence metadata is ephemeral; Caddy documents graceful reload and delayed streams; named Tailscale Services document host drain but not health-gated same-host target promotion; Mix does not provide hot upgrades out of the box; Docker rolling updates/resource limits require explicit policy; Nx cache correctness depends on complete inputs. Disposition: sources and corrections are integrated into [primary-source verification](tech-docs/README.md#primary-source-verification).
- **2026-08-27 — Deterministic AI operation requested.** The release should run fixed tests before creating an artifact and minimize routine AI context. Disposition: `[AC-04]` and the [deterministic release constraints](tech-docs/release-contract.md#deterministic-release-constraints) require a revision-bound, fail-closed state machine and bounded structured summaries.
- **2026-08-27 — Recommendation requested and replacement allowed.** The plan must choose a preferred solution without preserving existing mechanics by fiat. Disposition: [composed ephemeral blue/green Caddy](tech-docs/README.md#recommendation-and-ranking) remains recommended from current evidence; named-Service and single-slot Tailscale are conditional on complete measured proof.
- **2026-08-27 — Automatic recovery is not yet covered.** The canonical deployment-reconnect browser step calls `page.reload()`. It proves persistence across a reload, not automatic LiveView/WebSocket recovery, in-progress input preservation, or absence of duplicate actions. Disposition: Phase 1 requires a checked-in no-reload scenario before any live measurement.
- **2026-08-27 — Rollback has warm and cold forms.** `deploy:rollback` promotes the recorded previous slot only while it remains prepared. After `deploy:retire`, the retained artifact must be re-prepared and revision-checked before promotion. Disposition: both recovery edges are explicit in technical documentation and delivery.
- **2026-08-27 — Production cannot be the authenticated test data root.** Repository rules require synthetic identities and records to live under a marked, isolated test run and forbid testing through real sessions or production records. Disposition: Phase 1 must design and prove an isolated served verification surface; absent that proof, authenticated live-route measurement is blocked rather than weakened.
- **2026-08-27 — Rendered release labels were visibly clipped.** The supplied release-state screenshot shows transition text cut off even though the diagram remained renderable. Disposition: `[AC-06]`, the [Mermaid legibility prerequisite](tech-docs/release-contract.md#mermaid-legibility-prerequisite), and a deferred delivery task define a deterministic Badakmini/pre-push guard; no validator or hook code changes in this documentation-only iteration.
- **2026-08-27 — Technical set crossed the split threshold.** Alternative-specific diagrams, ports, resources, tests, WebSocket behavior, and migration detail made one file exceed the 400-line limit. Disposition: split into a decision guide, release contract, and migration design with distinct reader jobs; exact line totals are checked manually at each plan gate.
- **2026-08-27 — Safe host resource sample.** The host has 32 GiB RAM and 12 cores. Five one-second samples observed routed Phoenix at 75–76 MiB RSS/0.03–0.11 cores, Caddy at 57 MiB/0–0.09 cores, and Tailscale at 42 MiB/approximately 0 cores. Disposition: [absolute planning estimates](tech-docs/alternatives.md#absolute-planning-estimates) add conservative build/test and variance headroom; Phase 1 must replace estimates with p95/peak load evidence.
- **2026-08-27 — Workload and cadence clarified.** Bnest serves about 5–10 users across 1–3 groups, the host runs 5–10 development workloads, and releases occur daily or multiple times daily. Disposition: capacity admission reserves release/safety headroom without mutating development work; one host lock serializes and coalesces requests; qualification uses 10 synthetic clients across 3 groups and three repeated releases.
- **2026-08-27 — Future multiplayer continuity required.** Socket reconnect must preserve authoritative state, ordering, pending safe input, and exactly-once actions without reload. Disposition: game truth lives outside one LiveView process; versioned session/catch-up/idempotency and multi-browser proof are part of `[AC-03]`, but this plan does not build a game.
- **2026-08-27 — Future databases must not weaken rollback.** No engine or schema is selected, but every option must run one lock-owned expand–migrate–verify lifecycle and defer destructive contract work. Disposition: [migration design](tech-docs/migration-design.md) owns alternative behavior, provisional 5–10-user resource/connection budgets, tests, and stop conditions.
- **2026-08-27 — Expanded plan quality gate passed.** Recursive review found five plan-level documents and four technical companions; the technical set totals 660 lines and therefore correctly uses the split form. Uncached repository validation checked 211 Markdown files, 45 governed word budgets, 14 plan maps, and 32 Mermaid diagrams successfully after repairing the split directory map and two relative links. Disposition: Phase 0 is complete and the documentation is ready for its authorized commit/push; implementation remains governed by the deferred delivery phases.

The active route and artifact set were unchanged. Disposition: the gate environment now strips production runtime, deployment, origin, cookie, key, host, and listener values while retaining scheduler limits; a focused regression test passes before retry.
