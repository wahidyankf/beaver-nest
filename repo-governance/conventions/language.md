# Language

## Purpose

English gives contributors one working language for repository artifacts while leaving conversations open to the
people involved.

## Standards

English is the primary language for repository-authored content. Use English for source-code identifiers, comments,
documentation, specifications, test names and descriptions, configuration labels, repository guidance, and every
repository rule, including files under `repo-governance/`.

Use another language only when it is the subject of the content, required by an external interface or product
requirement, or quoted faithfully. Keep any surrounding explanation in English.

The English-only artifact rule does not set the language of conversations with contributors or users. Contributors may
communicate with agents in any language, including Bahasa Indonesia. When an agent writes in English to a user, the
clarity rule below applies.

Whenever writing in English, use clear, simple, natural words that readers who learned English later can understand.
Keep comments, commit messages, work notes, plans, and other documents as brief as their purpose allows. Explain why a
non-obvious choice was made, rather than only naming the choice. Preserve the behavior, steps, evidence, and other
details readers need to use, execute, or verify a document. In code comments, explain why a choice was needed instead
of repeating what the code already shows.

## Examples

In a plan, "Validate before writing so invalid inputs leave no files" gives both the step and its reason. "Validate
first" only names the step.

## Validation

Unenforced by tooling, by decision: review must judge whether the language is understandable, the reasons are useful,
and the document still contains the detail its readers need.
