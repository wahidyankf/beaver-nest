# Software Quality Enforcement

Apply this map to every repository change. Linked standards own detailed requirements; this document owns enforcement classification and routing.

## Enforcement Classes

- **Required gate:** automated completion blocker.
- **Commit gate:** automatic `git commit` blocker.
- **Push gate:** automatic `git push` blocker.
- **Scheduled detection:** cadence-based detection that never retroactively blocks a push.
- **Required evidence:** blocking human or agent review, not automation.
- **Runtime guard:** fails closed before unsafe test or deployment work.

Every applicable rule must truthfully name its class and route; missing automation never weakens it.

A row applies when a change can alter its outcome, boundary, artifact, or mechanism. Run its narrowest targets and record evidence before completion; scheduled coverage never replaces local proof.

Preserve applicable rows, results, and outstanding evidence through compaction or handoff under [governance continuity](../principles/governance-continuity.md); reload this map before resuming.

| Sufficient, consistent repository rules                              | [Rules quality gate](../workflows/rules-quality-gate.md) and [propagation](../workflows/rules-propagation.md)                                                       | **Required evidence:** semantic gate and propagation. **Required gate:** `badakmini-cli:test:repo` owns machine checks. **Push gate:** conditional.                                                                                                             | Every rule change.                                                                      |
| Safe active-service behaviour and intended routed revision           | [Live-service continuity](live-service-continuity.md)                                                                                                               | **Runtime guard:** unsafe qualification or health stops promotion. **Required evidence:** responsiveness, routed journey/revision, drain, and rollback proof. Project READMEs own resolved Nx commands and legitimate omissions. Nx projects, hooks, and scheduled CI implement this map but do not replace its rules.
